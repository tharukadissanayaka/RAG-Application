# API Specification

## Base URL

```
http://localhost:8000
```

## Authentication

Currently, no authentication is required. For production, add JWT or API key authentication.

## Response Format

All responses are JSON. Successful requests return 200, client errors return 4xx, server errors return 5xx.

### Standard Response Structure

```json
{
  "success": true,
  "message": "Description",
  "data": {}
}
```

## Endpoints

### 1. Health Check

**Endpoint**: `GET /health`

**Description**: Check if the API is running and healthy.

**Response**:

```json
{
  "status": "healthy",
  "service": "RAG API"
}
```

### 2. Root

**Endpoint**: `GET /`

**Description**: Get information about available endpoints.

**Response**:

```json
{
  "message": "Welcome to the RAG API",
  "endpoints": {
    "health": "/health (GET)",
    "ingest": "/ingest (POST)",
    "ask": "/ask (POST)",
    "stats": "/stats (GET)",
    "clear": "/clear (DELETE)",
    "docs": "/docs (GET)"
  }
}
```

### 3. Ingest Document

**Endpoint**: `POST /ingest`

**Description**: Upload and ingest a document into the vector store.

**Parameters**:

- `file` (FormData, required): The document file to ingest
  - Supported types: `.txt`, `.pdf`
  - Max size: 10MB (configurable)

**Example Request**:

```bash
curl -X POST "http://localhost:8000/ingest" \
  -F "file=@document.pdf"
```

**Response (Success)**:

```json
{
  "success": true,
  "file_name": "document.pdf",
  "chunks_created": 42,
  "message": "Successfully ingested document.pdf (42 chunks)"
}
```

**Response (Error)**:

```json
{
  "success": false,
  "error": "File type .doc not supported. Allowed: {'.txt', '.pdf'}"
}
```

**Status Codes**:

- `200`: File successfully ingested
- `400`: Invalid file type or other client error
- `413`: File too large
- `500`: Server error during processing

### 4. Ask Question

**Endpoint**: `POST /ask`

**Description**: Ask a question based on ingested documents.

**Parameters**:

- `question` (query string, required): The question to ask

**Example Request**:

```bash
curl -X POST "http://localhost:8000/ask?question=What+is+the+main+topic?"
```

**Response (Success)**:

```json
{
  "answer": "The document discusses machine learning and its applications in healthcare.",
  "context": [
    {
      "content": "Machine learning (ML) is a subset of artificial intelligence...",
      "source": "document.pdf",
      "similarity_score": 0.95
    },
    {
      "content": "In healthcare, ML algorithms can diagnose diseases...",
      "source": "document.pdf",
      "similarity_score": 0.89
    }
  ],
  "question": "What is the main topic?",
  "success": true
}
```

**Response (Error - No Documents)**:

```json
{
  "answer": "I don't know. (No documents ingested yet)",
  "context": [],
  "error": "Please ingest documents first using the /ingest endpoint"
}
```

**Response (Error - No Answer)**:

```json
{
  "answer": "I don't know.",
  "context": [],
  "question": "What is quantum computing?",
  "success": true
}
```

**Status Codes**:

- `200`: Question processed successfully
- `400`: Empty question or missing documents

### 5. Get Statistics

**Endpoint**: `GET /stats`

**Description**: Get information about the vector store.

**Response**:

```json
{
  "vector_store": {
    "success": true,
    "total_documents": 42,
    "vector_store_path": "./chroma_db"
  },
  "documents_count": 42
}
```

**Status Codes**:

- `200`: Stats retrieved successfully

### 6. Clear Vector Store

**Endpoint**: `DELETE /clear`

**Description**: Remove all documents from the vector store.

**Response (Success)**:

```json
{
  "success": true,
  "message": "Vector store cleared successfully"
}
```

**Response (Error)**:

```json
{
  "success": false,
  "error": "Error message"
}
```

**Status Codes**:

- `200`: Vector store cleared
- `500`: Server error during clearing

### 7. Interactive API Documentation

**Endpoint**: `GET /docs`

**Description**: Interactive Swagger UI documentation (auto-generated by FastAPI).

## Error Handling

All error responses follow this format:

```json
{
  "detail": "Error message describing what went wrong"
}
```

### Common Error Codes

| Code | Meaning               | Solution                            |
| ---- | --------------------- | ----------------------------------- |
| 400  | Bad Request           | Check request format and parameters |
| 413  | Payload Too Large     | Upload a smaller file               |
| 500  | Internal Server Error | Check server logs                   |

## Rate Limiting

- Free tier Groq API: 30 requests/minute
- Application has no rate limiting (implement for production)

## Chunk Management

When documents are ingested, they are split into chunks:

- **Chunk Size**: 1000 characters
- **Chunk Overlap**: 200 characters
- **Chunks Retrieved**: Top 3 most similar chunks per question

## LLM Configuration

- **Model**: Groq mixtral-8x7b-32768 (default)
- **Temperature**: 0.7 (moderate creativity)
- **Max Tokens**: 500 per response
- **System Prompt**: Enforces context-only responses

## Best Practices

### Request Best Practices

1. **File Upload**
   - Upload text files as UTF-8 encoded
   - Split large documents (>50MB) into smaller chunks
   - Use PDF files for formatted documents

2. **Questions**
   - Keep questions concise (< 200 characters)
   - Be specific about what you're asking
   - Avoid ambiguous questions

3. **Error Handling**
   - Always check response status codes
   - Handle "I don't know" responses gracefully
   - Implement retry logic for transient failures

### Response Interpretation

- **Similarity Score**: 0-1, where 1.0 is perfect match
- **Context**: Retrieved document chunks with source file
- **Answer**: Based strictly on provided context

## Examples

### Complete Workflow Example

```bash
# 1. Ingest a document
curl -X POST "http://localhost:8000/ingest" \
  -F "file=@research_paper.pdf"

# 2. Check stats
curl "http://localhost:8000/stats"

# 3. Ask a question
curl -X POST "http://localhost:8000/ask?question=What+are+the+key+findings?"

# 4. Ask another question
curl -X POST "http://localhost:8000/ask?question=What+methodology+was+used?"

# 5. Clear when done
curl -X DELETE "http://localhost:8000/clear"
```

### Python Client Example

```python
import requests

API_URL = "http://localhost:8000"

# Upload file
with open("document.pdf", "rb") as f:
    response = requests.post(
        f"{API_URL}/ingest",
        files={"file": f}
    )
    print(response.json())

# Ask question
response = requests.post(
    f"{API_URL}/ask",
    params={"question": "What is this document about?"}
)
print(response.json())
```

### JavaScript Client Example
